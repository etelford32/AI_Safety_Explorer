# AI Safety Explorer v0.34.0

**Bring the conversations you already have, and read them by meaning. By Elliot Telford.**

AI Safety Explorer is an open research instrument for one question: *when the framing of a
request gets riskier while the reasoning task stays the same, how does a model's behaviour
change?* This release brings in three development versions (v0.32, v0.33 and v0.34). It does
four things:

- every screen now states in plain words what it found;
- any conversation history can be dropped in, and the Explorer recognises it;
- register is read by meaning, trusted only in the languages where that reading was validated;
- the Mac app is a disk image that runs on Intel as well as Apple Silicon.

## Download

**[Download for Mac (.dmg)](https://github.com/etelford32/AI_Safety_Explorer/releases/latest/download/AI-Safety-Explorer-macOS.dmg)**
Requires macOS 11 or later, on **Intel or Apple Silicon**. The file is
`AI-Safety-Explorer-macOS.dmg` in the assets below.

1. Open the disk image and drag **AI Safety Explorer** onto **Applications**.
2. Open the app. The first time only, macOS asks you to approve it, because the app is not yet
   notarized by Apple:
   - **macOS 15 and later:** click **Done**. Then go to **System Settings → Privacy &
     Security**, click **Open Anyway** and confirm.
   - **macOS 14 and earlier:** right-click the app → **Open** → **Open**.

From then on the app keeps itself up to date. It checks each new version before switching to
it, and goes back to the last version that worked if a new one fails. See the full guide:
[docs/INSTALL.md](https://github.com/etelford32/AI_Safety_Explorer/blob/main/docs/INSTALL.md).

**Already have the app?** It updates itself to v0.34.0 the next time it launches (stable
channel). Your database is upgraded in place and nothing is lost.

**From source (any OS, Python 3.11+):** `git clone` the repository, then run
`pip install -e '.[dev]'` and `explorer serve`. There are no third-party runtime
dependencies, and that still holds with the new embedding backends.

## New: conversations are recognised automatically (v0.33)

Getting data in used to mean picking the right import option and reshaping your files to fit it.
Now you drop the data in as it is.

- **Drop or paste anywhere.** Drop files, folders or zips on any view, or paste a conversation.
  You see a preview of what was found before anything is stored.
- **Formats are recognised by their contents, not the file extension.** Supported formats:
  - ChatGPT and Claude.ai data exports;
  - Claude Code and Codex CLI session logs;
  - OpenAI and Anthropic message files, and ShareGPT files;
  - prompt/response JSON, JSONL and CSV;
  - labelled transcripts;
  - any JSON whose lists read as messages.

  Roles are read from the file, never guessed. Tool calls stay in place as tool turns. Hidden
  scaffolding, reasoning and images are left out and counted.
- **Picked up automatically.** Anything saved into the **inbox** folder is imported. Folders you
  connect (Claude Code, Codex CLI, or any other folder) are re-checked every few seconds, and only
  files that changed are re-read. The Explorer finds likely sources by reading file names only,
  and opens nothing until you connect or import it.
- **Safe to import twice.** Importing the same export again adds nothing. A log that has grown
  adds only its new turns. An edited conversation is kept as a branch.
- **Your own chats can be scored.** A conversation that opens with a corpus prompt also becomes
  a Tier B run, scored against that prompt's answer key.
- **Triage on arrival.** Every conversation is read as it arrives and flagged:
  - a shift in register;
  - refusals;
  - talk of being tested;
  - high expressed agency;
  - an answer key.

  **Conversations** (renamed from Sessions) searches, filters and sorts thousands of them by
  *worth a look*.
- The browser userscript has a new **every chat on this site** mode. `explorer import`
  recognises formats from the terminal, and `explorer sources` manages watched folders.

## New: semantic reading you can trust per language (v0.34)

Register means warmth, moralising, distancing, refusal and expressed agency. The phrase lexicon
misses register that uses no stock phrase: a warm reply that never says "let's", or a refusal
that never says "I can't". An embedding reads meaning instead. Until now, the only real
embedding backend needed PyTorch, which cannot ship inside the app.

- **Backends that need no Python package:**
  - **Ollama** on your own computer. It is free and private, and it is recommended with
    `bge-m3`, which covers 100+ languages.
  - **LM Studio**.
  - **OpenAI**, **Voyage AI**, or any OpenAI-compatible server such as llama.cpp or vLLM.

  The app gets them as an ordinary update, with no new download.
- **One panel to set it up.** Open **Semantic reading** from the *register* chip on the Overview,
  from ⌘K, or from *Needs a look*. The panel finds backends on your computer, downloads an Ollama
  model with one click, tests the backend, and makes it active.
- **Nothing is trusted on the backend's say-so.** Before a backend becomes active, held-out probe
  sentences are placed on every axis. These probes share no content words with the exemplars. The
  probes are also translated into **French, Spanish and Japanese** and projected onto the English
  axes. Each reading is marked trustworthy only in the languages its backend passed. An
  English-only model is therefore not trusted to read a Japanese conversation.
- **Imported conversations are tagged with their language.** In a language with no validated
  lexicon, drift is measured by a trusted embedding alone.
- **Switching backends needs no restart.** Every conversation's triage is re-read in the
  background. Vectors are cached on disk, so no text is embedded twice.
- **No hangs if the backend goes away.** If Ollama stops or the network drops, readings fall back
  to the untrusted lexicon, the panel says why, and the backend is retried every minute.
- **Private by default.** The local backends keep everything on your computer. For a cloud backend,
  the panel names where the text goes before you choose it. API keys are kept in a file only you
  can read, and they are never sent back to the page.
- `explorer embed` does the same from a terminal. See
  [docs/SEMANTIC.md](https://github.com/etelford32/AI_Safety_Explorer/blob/main/docs/SEMANTIC.md).

## New: every number says what it means (v0.32)

Each view was reviewed against one question: could someone who has not read the pre-registration
say what this screen found?

- **Plain answers.** Each analysis states its result in a sentence. For example: *"Yes, in intent.
  When the intent framing turns risky, expert phrasing loses 0.41 more capability…"*. The Overview
  tile and the Results panel share that sentence, so they cannot disagree.
- **Status is an icon plus a word, not colour alone:** *Finding*, *Review*, *Clean* or *No data*.
- **Charts show their scales.** Mini charts label their axis ends and give a key where colour
  matters. Every mark has a tooltip.
- **Readable text.** All text meets WCAG AA contrast.
- **No view opens empty.** Surface and Compare open on real content, and demo data says it is demo
  data on every view.

## Fixed

- The app had no embedding reading at all, because the anchor file was opened relative to the
  working directory.
- Asking for the `minilm` backend silently fell back to hashing, because nothing loaded it.
- Importing a large history was slow, because corpus matching rebuilt its index for every
  message. The index is now cached.
