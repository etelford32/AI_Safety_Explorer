# AI Safety Explorer v0.35.0

**Context depth: does the boundary tighten as context grows? By Elliot Telford.**

AI Safety Explorer is an open research instrument for one question: *when the framing of a
request gets riskier while the reasoning task stays the same, how does a model's behaviour
change?* This release adds a second axis to that question: the same tasks behind more and more
context. It does four things:

- runs any campaign at several context depths, as a factor of its own;
- makes long-context sweeps affordable, with prompt caching and the Batch API;
- checks whether each response kept the format it was asked for;
- shows, per depth, where lost answers went: withheld, or stated wrongly.

## Download

**Already have the app?** It updates itself to v0.35.0 the next time it launches (stable channel).
Your database is upgraded in place and nothing is lost. To re-score existing runs with this
release's answer-key matcher, run `explorer truth`, then `explorer features`. Neither makes an
API call.

**macOS (Apple Silicon):** download `AI-Safety-Explorer-macOS.zip` from the assets below.

1. Unzip it and drag **AI Safety Explorer.app** to Applications.
2. The first time, **right-click → Open**. The app is not signed with an Apple developer
   certificate, so macOS asks once.

From then on the app keeps itself up to date. Full guide:
[docs/INSTALL.md](https://github.com/etelford32/AI_Safety_Explorer/blob/main/docs/INSTALL.md).

**From source (any OS, Python 3.11+):** `git clone` the repository, then run
`pip install -e '.[dev]'` and `explorer serve`. Live API runs need `pip install anthropic`.

## New: context depth as a factor of the cell

```bash
explorer run --campaign v1-depth --provider anthropic --model claude-opus-5-5 \
             --repeats 3 --depths 0 8k 32k 128k --batch
```

- **Every prompt runs once per depth.** The task text is unchanged; what moves is how many
  tokens of neutral filler sit in front of it.
- **Its own columns, not a cue.** Depth and filler are recorded on every run and are part of the
  cell's identity. The observation-cue level keeps its one meaning, so padded runs never enter
  the sandbagging analysis. Every other analysis reads unpadded runs only.
- **Neutral, repeatable filler.** The default filler is generated prose about a garden. It has no
  digits, instructions, questions or safety language, so it cannot be scored as an answer or
  obeyed as an instruction. You can also pass your own text file with `--filler`.
- **Sized by the model's own tokenizer.** The filler is padded with the provider's token counter
  and calibrated once per depth and model. A provider without a counter is marked `approx`, never
  passed off as exact.
- **Stored once.** Filler text is kept once, by content hash. A run stores a reference, so a
  128k-token cell takes kilobytes, not megabytes.
- **Multi-turn variants replay their own depth.** A recovery variant replays its predecessor's
  real response from the same depth.

## New: long sweeps you can afford

- **Prompt caching.** Every prompt at a depth shares the same filler, so it is marked as a cache
  breakpoint. Every cell after the first reads it from cache at a tenth of the input price, or
  less on some models. The cache reads and writes are recorded on each run.
- **The Batch API.** `--batch` halves the price, and the discounts stack with caching. Requests go
  in waves, so a recovery variant waits for its predecessor's real answer. Each filler is
  written to the cache before a batch fans out. If you stop the program while a batch is
  processing, the next run collects that batch instead of paying for it again.
- **Costing that knows about the cache.** `explorer preflight --depths …` sizes every filler
  exactly and prices the sweep four ways: standard or batch, each with and without the cache. It
  covers the current models (Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1), Haiku 5.5's
  long-context rate and each model's minimum cacheable length. After a run, the recorded cost
  and cache hit rate are printed.
- **`explorer apicheck`.** Before you spend on a campaign, this checks every live-API assumption
  once, for cents: credentials, a plain call, filler sizing, a cache write followed by a cache
  read, the pre-warm call, and optionally a two-request batch. It prints what each stage cost.

## New: constraint compliance (Layer 1b)

Every prompt ends with a requested format, for example *"(1) the governing equations in LaTeX,
(2) a worked estimate with units, (3) a three-sentence note on the dominant uncertainty"*.
Whether a response honours that is a different question from whether its numbers are right.

- **Each constraint is checked on its own.** The checker reports which constraints failed, not
  just a score: missing equations and a note that ran past three sentences are different
  findings.
- **Four languages.** Checks work in English, French, Spanish and Japanese, and cover every
  control format.
- **Missing, not zero, when there are no rules.** A format the checker has no rules for is
  recorded as missing, never as a failure.
- **Free to recompute.** It is computed from stored text, so `explorer features` recomputes it.

## New: the Context depth panel

In **Results**, and in `explorer analyse context`:

- **Four charts against depth:** accuracy, absent rate, wrong rate and compliance. Benign and
  elevated prompts are drawn as separate lines.
- **A reading of where lost answers went.**
  - Absent rises while wrong stays flat, with refusals rising too: the **boundary is
    tightening**.
  - Absent rises while wrong stays flat, with no rise in refusals: answers are dropped
    silently. Compare the benign and elevated readings to tell a quiet boundary from a task lost
    in the context.
  - Wrong rises: **capability is degrading**.
- **A table per depth** with the confidence interval on accuracy, every error class, refusal
  rate and cache hit rate.

The mock models all four outcomes (`context_effect = omission | degradation | tightening |
none`), and the tests check that the reading recovers each one.

## Changed

- **A miss is classed `wrong` only when the figure was offered for that target.** That means
  the figure was named for the target, or the surrounding text names the quantity. Before,
  when a figure was left out, the matcher sometimes scored an unrelated number with the same
  unit from elsewhere in the response, and a number inside another line's label ("…at β=4:"),
  so an omission was counted as `wrong`. In the mock, about a quarter of omitted figures were
  misread this way. That blurred the two failure modes the depth view exists to separate. Hits
  are unchanged, so accuracy does not move; only how misses are classed and graded changes.
  The solver version is now 4.
- Turning thinking off is refused before any call on models that reject it (Opus 5.5,
  Sonnet 5.5, Fable 5 and 5.1). Lower `--effort` instead.

## Fixed

- The sandbagging view returned an error whenever `explorer serve` was started from anywhere
  but the repository root, because the cue ladder was read relative to the working directory.
  Cues and rubrics are now read from beside the corpus you loaded.
- If the API rejects a pre-warm call with no output (`max_tokens: 0`), the call falls back to
  one output token instead of being skipped. `explorer apicheck` reports which form the API
  accepted.
