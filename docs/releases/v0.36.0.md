# AI Safety Explorer v0.36.0

**A Mac app that updates itself, and a pilot you can read at a glance. By Elliot Telford.**

AI Safety Explorer is an open research instrument for one question: *when the framing of a
request gets riskier while the reasoning task stays the same, how does a model's behaviour
change?* This release does four things:

- the Mac app is a disk image for Intel and Apple Silicon, and it now replaces itself when a
  release ships a newer one;
- `explorer summary` lays out a set of campaigns side by side, starting with how every call
  ended;
- the analysis reads the API's own refusal stop as a result in its own right, and reads
  correctness only where the model answered (Amendment A1.9). The power simulator models
  the stop too;
- three faults in how a finished run was reported are fixed. The first live baseline turned
  them up.

## Download

**[Download for Mac (.dmg)](https://github.com/etelford32/AI_Safety_Explorer/releases/latest/download/AI-Safety-Explorer-macOS.dmg)**
Requires macOS 11 or later, on **Intel or Apple Silicon**. The file is
`AI-Safety-Explorer-macOS.dmg` in the assets below.

1. Open the disk image and drag **AI Safety Explorer** onto **Applications**.
2. Open the app. The first time only, macOS asks you to approve it, because the app is not yet
   notarized by Apple:
   - **macOS 15 and later:** click **Done**. Then go to **System Settings → Privacy &
     Security**, click **Open Anyway** and confirm.
   - **macOS 14 and earlier:** right-click the app → **Open** → **Open**.

From then on the app keeps itself up to date. See the full guide:
[docs/INSTALL.md](https://github.com/etelford32/AI_Safety_Explorer/blob/main/docs/INSTALL.md).

**Already have the app?** It updates its Explorer code to v0.36.0 the next time it launches
(stable channel). To get the Intel build and an app that replaces itself, download the new app
once. From then on that happens on its own.

**From source (any OS, Python 3.11+):** `git clone` the repository, then run
`pip install -e '.[dev]'` and `explorer serve`. Live API runs need `pip install anthropic`.

## New: an app that updates itself

The app already fetched, checked and started the newest Explorer code on every launch. Now the
app around that code updates too. That covers the launcher, its Python, and the Anthropic and
OpenAI SDKs it carries.

- **Found.** Each release publishes `app.json`, which names the version of the app inside it.
  The app checks it shortly after it starts and then every half hour.
- **Checked before it is used.**
  - The download must match the release's published size and SHA-256.
  - It must carry this app's identity and the promised version, and its code signature must
    verify.
  - Once releases are signed with a Developer ID, the update must come from the same developer.
- **Installed when you quit**, or at once with **Updates → Restart**. If the swap fails, the old
  app is put back and the next launch says why. Data and settings are untouched.
- **Declines when it can't replace itself, and says why.** That happens with a copy opened from
  the disk image or from Downloads. You get the download link instead.
- **Tested for real before each release.** CI installs a copy of the built app, serves it a
  newer release, and requires that it replace itself and then run.

## New: a proper Mac download

- **A disk image** with the usual drag-to-Applications window. The zip is still attached.
- **Intel as well as Apple Silicon.** Every binary in the app carries both architectures.
  Before, two libraries inside the Anthropic and OpenAI SDKs were Apple Silicon only. CI checks
  every binary with Apple's `lipo` and runs the Intel build under Rosetta.

  `releases/latest/download/AI-Safety-Explorer-macOS.dmg`.
- **Tested the way you get it.** CI opens the disk image read-only and runs the app from it.
- **Signing ready.** When the repository has an Apple Developer ID, releases are signed and

## New: `explorer summary`

```bash
explorer summary --prefix baseline- --out data/summary/baseline
```

- **Run health first.** For each campaign it shows how many calls finished, how many were cut
  off at `max_tokens`, how many ended with the API's refusal stop, and how many errored. It
  also shows the settings and the cost. Cut-off responses are excluded from every analysis,
  so a model that truncates often is read on a skewed subset. The summary says so, and warns
  when campaigns differ in settings, repeats or corpus version.
- **Then the API stop.** Stops by family, with blocked families marked, then the share of
  each rung's calls the API stopped, and the paired change against the twin (A1.9, part 1).
- **Then correctness where the model answered, model by model** (part 2). For each campaign
  it shows graded correctness against the twin: the ladder (C vs B, D vs C, E vs C, and F,
  the recovery after E), the depth arm, the language arm per language, and the control
  arms. Beside it, the same reading over all pairs, with stops scored as they fell.
- **Safe to share.** `SUMMARY.md` and `summary.json` hold aggregates only, with no prompt or
  response text.
- `scripts/baseline.sh` (the corpus against Opus, Sonnet and Haiku 5.5) and `scripts/pilot.sh`
  (the staged live-API plan) end with it. `baseline.sh` is now safe to re-run: finished cells
  are skipped, so a second run only redoes the read-out.
- Organisation-level API keys work: set `ANTHROPIC_WORKSPACE_ID`.

## New: the API stop is read, not scored as zero (Amendment A1.9, draft)

In the first baseline the API, not the model's prose, ended 36% of calls with
`stop_reason = refusal`, mostly by topic. Under the outcome as first written, a pair
stopped on both sides scored 0 against 0 and read as "no change". A1.9 splits the outcome
in two. It takes effect when it is merged, before any confirmatory data.

- **Part 1, the API stop.** The share of each rung's calls stopped, with a Wilson interval,
  and the paired change against the twin. Two new confirmatory hypotheses read it: H14 (the
  stop rises with risk framing) and H15 (it carries into the legitimate follow-up). The
  Holm family becomes m = 10.
- **Part 2, correctness where the model answered.** Every correctness hypothesis is read
  over pairs where neither side was stopped. A family the API stops on ≥ 90% of its benign
  calls (judged on at least 4) is *blocked* for that model and left out. Each result also
  carries the all-pairs reading, and is marked *stop-sensitive* if the sign differs.
- **The language arm** is not testable for a language whose answered pairs come from fewer
  than two families.
- **`explorer paper`** writes both parts, names blocked and undetermined families in its
  manifest, never prints an interval as `nan`, and marks campaigns created before A1.9 as
  exploratory.

## New: the power simulator models the stop

A stopped call carries no correctness information, so the real campaign reads fewer pairs
than it runs, and a blocked family drops out. A1.9 lets no confirmatory campaign be sized
until the simulator accounts for that.

- **`explorer power --stops-from <pilot>`** fits the pilot's stops by family and rung
  (logit P(stop) = family offset + rung effect), prints the pilot's counts beside the fitted
  rates, and has the simulated model stop calls at those rates.
- **Every correctness test is read as the paper reads it**, where the model answered. A
  `families` column gives the fewest families each test was read on.
- **H14 and H15 are simulated** by planting the stop's rise from C to D, E and F.
- **`--noise-from` reads answered runs only.** A prompt stopped on every repeat scores 0
  each time, and its zero spread used to pull the noise estimate down.
- **`scripts/baseline.sh`** now sizes the study once per model, with both flags.

In a test simulation shaped like Opus's pilot stops, with `network_propagation` blocked and
most of `orbital_debris` stopped, the cue test (H11b) was read on 2 of its 4 families. The
real figure for each model comes from running it on that model's baseline.

## Fixed

- **`explorer export --campaign <name>` wrote empty files.** It compared the name with the
  campaign's internal id. It now accepts the name or the id, and an unknown name is an error
  rather than an empty file.
- **The twin table pooled two comparisons.** A translated prompt carries its English twin's
  letter (C.ja is variant C). So the C, D and E rows mixed the English ladder step with each
  translation against its English twin. The table, and the Results view in the app, now show
  three arms separately: the ladder, the depth arm, and the language arm with one row per
  rung and language. B against A reads "not comparable" rather than "no data": A states no
  parameters, so there is no answer key to compare against. `explorer paper` was not affected,
  because it already read the ladder alone.
- **Truncation went unreported.** `explorer run` now ends by saying how many responses were cut
  off and what that means for the analysis. OpenAI's `length` and Anthropic's
  `model_context_window_exceeded` now count as cut off too. Before, only `max_tokens` did.
