# Content policy for the prompt corpus

This is a binding constraint on the corpus, enforced by `explorer lint`, not a
disclaimer.

## The core rule

> **The instrument varies framing over non-hazardous substrate.**

Every prompt variant — including those labelled "explicitly harmful" — must request
technical substance that satisfies at least one of:

- **(a) Published baseline.** The information is standard undergraduate or textbook
  material, freely available in any library.
- **(b) Abstract.** The request is purely mathematical or algorithmic with no
  physical realisation specified.
- **(c) Synthetic referent.** The target system is fictional, with invented names,
  parameters and topology that do not correspond to any real system.

The *harmful* element in a high-`intent` variant is the **stated purpose**, not the
sensitivity of the information requested. A variant that would provide meaningful
uplift if answered is a **corpus bug** and must be rewritten or removed.

## Why this is better science, not just safer

A naive design conflates two different phenomena:

1. the model reacting to *how a request is framed*, and
2. the model withholding *genuinely dangerous information*.

If the E-variant asks for real uplift, a refusal is correct and uninformative — we
have measured that the model declines to do harm, which we already knew. By holding
the substrate non-hazardous, a refusal becomes *informative*: it tells us the model
is responding to framing, and the twin comparison tells us exactly how much
legitimate capability that framing cost.

This is also what makes `over_refusal` measurable at all. Over-refusal is only
definable when we know, by construction, that the withheld information was safe.

## Practical constraints by family

| Family | Substrate rule |
|---|---|
| Scientific dual use | Orbital mechanics at textbook level; no real asteroid/satellite targeting parameters |
| Simulation | Scaling laws and N-body integration; no device physics, no weapon yields |
| Cybersecurity | Fictional network topology, invented software names; epidemiological maths only, no exploit code |
| Autonomous agents | Control-theory framing; fictional actuators; no real infrastructure endpoints |
| Persuasion | Fictional audiences; no real individuals, no real demographic microtargeting data |
| Privacy | Wholly synthetic datasets generated by the corpus itself; no real records |
| Dangerous engineering | Published failure modes; no bypass procedures for real safety systems |
| Human/medical safety | Physiology at textbook level; no individualised dosing, no real drug protocols |

## Hazard review

Every variant carries a `hazard_review` field with a sign-off:

```toml
hazard_review = "clear"           # reviewed, meets (a), (b) or (c)
hazard_rationale = "Two-body perturbation theory; standard Vallado Ch.9 material."
```

`explorer lint` fails if any non-stub variant lacks `hazard_review = "clear"` with a
non-empty rationale. Values `pending` or `flagged` block the variant from running.

## No real targets, ever

The `specificity` dimension goes to 4 = "real, named target/system." In this corpus,
"real" means *a real system class that genuinely exists and is publicly documented*
— low Earth orbit, a municipal water treatment process, the TCP handshake — not a
specific named instance that could be attacked. The linter maintains a deny-list of
patterns (IP addresses, CVE identifiers, named facilities, real personal names) and
fails on any match.

## Reporting

If a run produces a response that *does* contain meaningful uplift — i.e. the model
supplied something the corpus did not ask for and should not have — that is a
finding worth reporting to the model provider, not worth publishing. The annotation
UI has an `escalate` flag for exactly this, and escalated responses are excluded
from exported datasets.
